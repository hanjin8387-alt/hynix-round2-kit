# SK하이닉스 2차 예선 준비 키트

Sol 6.1·Luna 6·Terra 5.6이 함께 사용하는 공통 지침과 선택형 스킬 5개다. 응시 환경에 제공된 Codex에서 사용한다. 추가 MCP나 개인 API 키는 필요하지 않다.

## 시험장에서 적용하기

아래 명령은 **시험 웹 IDE 안의 터미널**에서 실행한다. 과제 파일이 있는 폴더는 그대로 둔다.

```bash
git clone --depth 1 https://github.com/hanjin8387-alt/hynix-round2-kit.git /tmp/hynix-round2-kit
codex
```

이미 Codex가 열려 있으면 별도 터미널에서 clone만 하고 기존 대화를 이어가면 된다. `/tmp/hynix-round2-kit`이 이미 있으면 다시 clone하지 말고 기존 파일을 확인한다. 시험 중 내려받기·파일 접근이 차단되면 제한을 우회하지 말고 Cofa Helper 또는 문제 신고를 이용한다.

Codex 입력창에 다음을 전달한다.

```text
지금은 과제 구현 단계다. /tmp/hynix-round2-kit이 없으면 https://github.com/hanjin8387-alt/hynix-round2-kit.git 을 그곳에 clone하고, 있으면 재사용해.
그 안의 AGENTS.md를 읽고 이 대화의 보조 지침으로 적용해 줘.
먼저 실제 과제 루트와 적용 중인 AGENTS.md·AGENTS.override.md를 확인하고, 기존 과제 지침을 우선해.
키트의 .agents/skills에 있는 hynix-* 폴더 5개를 참고자료까지 과제 루트의 .agents/skills로 복사해 줘.
동일 이름이 이미 있으면 비교해서 같으면 재사용하고, 다르면 기존 파일을 보존하고 차이를 알려 줘. 전역 설정은 바꾸지 마.
과제 루트에 AGENTS.md와 AGENTS.override.md가 모두 없을 때만 키트 AGENTS.md를 복사해.
기존 지침 파일과 과제 README는 수정하지 말고, 키트의 공통 규칙은 지금 직접 읽어 적용해.
실제로 적용한 경로와 충돌 여부를 짧게 알려 줘. 스킬이 목록에 없어도 해당 SKILL.md를 직접 읽어서 사용해.
그다음 hynix-triage로 실제 과제 안내를 읽고 필수 결과·완료 기준·실무자에게 물을 질문부터 정리해 줘.
```

플랫폼에 표시된 **과제 남은 시간**도 함께 알려 준다. 14:00은 서술형까지 포함한 전체 마감이며, 과제 타이머와 다르다.

같은 대화에서 모델을 바꿔도 지침을 별도로 복제할 필요는 없다. `/status`로 현재 모델을 확인하고 변경이 필요할 때만 `/model`을 사용한다. 가능한 한 기존 대화를 이어간다. 새 대화나 Codex 재시작 후에는 위 적용 요청과 필요한 작업 요약을 다시 전달한다. 스킬 자동 발견이 되지 않으면 `.agents/skills/hynix-triage/SKILL.md`처럼 파일 경로를 직접 지정한다.

## 진행하면서 쓰는 요청

| 상황 | Codex에 입력할 예시 |
| --- | --- |
| 과제 파악·요구 변경 | `$hynix-triage 필수 요구와 확인 질문을 정리해 줘.` |
| 구현 | `$hynix-build 정리된 요구를 사용해 핵심 기능부터 완성하고 확인해 줘.` |
| 실무자 답변 도착 | `실무자가 이렇게 답했어: … 기존 가정과 비교하고 영향받은 부분만 갱신해 줘.` |
| 제출 전 점검 | `$hynix-verify 성공한 검증은 재사용하고 필수 조건의 누락과 오류를 확인해 줘.` |
| 제출 전 읽기 복습 | `$hynix-explain 지금은 제출 확정 전이야. 중요한 결정과 검증 근거를 쉬운 말로 짧게 정리해 줘.` |
| 직접 설명 연습 | `$hynix-explain 제출 확정 전, 5분만 연습하자. 하나씩 질문하고 내 답을 듣고 점검해 줘.` |
| 실제 반도체 데이터 분석 | `$hynix-semiconductor 이 데이터의 집계 단위·분모·검사 이력을 확인해 줘.` |

다섯 스킬을 매번 순서대로 호출할 필요는 없다. 구현 중 확인한 결과는 제출 점검에서도 재사용한다. 반도체 스킬은 해당 과제에서만 사용한다.

## 시간과 제출

180분을 모두 사용할 수 있다면 다음처럼 나눌 수 있다. 고정 단계가 아니라 시작 예시이며 실제 남은 시간에 맞춰 줄인다.

- 처음 15분: 적용·요구 파악·중요 질문.
- 다음 110분: 핵심 구현과 변경 부분 확인, 실무자 답변 반영.
- 다음 30분: 필수 조건 점검과 오류 수정, 요구된 문서 정리.
- 다음 15분: 설명 복습과 저장 확인.
- 마지막 10분: 사용자가 제출 진행.

전체 마감에서 후속 6문항×5분과 질문 생성 대기·최종 처리 여유가 부족하면 구현을 더 일찍 마친다. 제출물 확정 이후에는 이 키트의 AI 사용을 중단한다. 복습은 질문 생성 대기 시간이 아니라 제출 확정 전에 끝낸다.

공개 준비 자료를 가져오는 Git Clone과 시험 작업을 외부로 올리는 Git Push는 다르다. 시험 중에는 문제·데이터·코드·결과물을 외부로 전송하거나 저장소에 올리지 않는다. 개인 PC의 비공개 파일 업로드도 사용하지 않는다.
