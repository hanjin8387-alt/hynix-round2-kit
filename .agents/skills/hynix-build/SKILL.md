# 실행되는 결과 만들기

현재 코드와 최근 실행 결과에서 작업을 이어간다. 정리된 요구와 완료 기준은 재작성하지 않고 사용하며, 빠진 결정만 보완한다. 기존 도구로 필수 결과를 만들 수 있으면 그 구조를 유지한다.

## 한 번에 끝낼 단위

실제 입력을 받아 필요한 처리를 거쳐 의미 있는 결과를 보여주는 한 가지 사용 사례를 끝낸다. 저장이 요구되면 저장 후 다시 읽는 과정까지 포함한다. 분석이라면 계산과 해석을 연결하고, 문서 과제라면 근거와 결론이 대응하게 한다.

가짜 성공 응답이나 고정 출력으로 기능을 대신하지 않는다. 시연 데이터가 필요하면 그 사실을 표시하고 실제 입력 처리와 구분한다. 동작하는 첫 결과에 필수 조건을 덧붙이며, 요구하지 않은 앱 화면이나 예측 모델은 추가하지 않는다.

## 변경과 오류 처리

- 목적에 맞는 작은 변경을 적용하고 현재 실행 방법을 유지한다. 의존성 추가는 얻는 기능이 설치·실행 비용을 정당화할 때만 한다.
- 실패하면 첫 오류를 작은 입력으로 재현하고 원인 하나를 수정한다. 서로 관련 없는 여러 해결책을 한꺼번에 적용하지 않는다.
- 반복 설치·연결 실패는 기존 도구로 대체할 수 있는지 판단한다. 플랫폼에서 차단한 기능은 우회하지 않고 오류 정보를 정리한다.
- 독립 작업을 병렬로 처리할 때도 제공 기능과 사용자 지시 범위에서 진행한다. 편집 파일이 겹치거나 메모리 부담이 커지면 순차 처리한다.
- 웹서버는 응답 준비를 짧게 확인한 뒤 다음 작업을 진행한다. 계속 실행되는 서버의 종료를 기다리며 작업을 멈추지 않는다. 사용자가 유지할 서버 터미널과 실행 명령을 알린다.

핵심 선택이 생기면 이유·관련 대안·남은 제약을 공통 지침의 기록 위치에 남긴다. 구현하지 않은 효과를 달성했다고 기록하지 않는다.

## 마칠 때

변경한 동작을 필요한 범위에서 실행해 확인하고 방법·결과·남은 문제를 전달한다. 제출 전 검증에서는 이 증거를 재사용할 수 있게 한다. 필수 기능이 통과하면 불필요한 재설계로 확장하지 않는다. 시간이 부족할수록 부가 기능보다 잘못된 결과와 제출 누락을 먼저 고친다.
