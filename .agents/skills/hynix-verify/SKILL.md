# 제출 가능한지 판단하기

필수 요구 전체를 현재 파일과 실행 증거에 대조한다. 완료했다는 설명이나 파일 존재만으로 통과 처리하지 않는다. 현재 코드·설정·의존성·데이터에도 유효한 성공 기록을 재사용하고, 변경 영향이나 증거가 없는 부분만 확인한다.

## 확인할 순서

1. 필수 파일과 기능이 요구한 위치·형식으로 존재하는지 살핀다. 내용 없는 틀이나 임시 문구가 남아 있지 않은지 확인한다.
2. 안내된 명령으로 핵심 사용 사례를 실행한다. 설치 완료와 실제 동작을 구분하고, 오류 시 가장 먼저 막힌 원인을 찾는다.
3. 결과를 크게 바꿀 경계 입력과 실패 입력을 고른다. 데이터 집계는 분모·단위·중복·누락을, 저장 기능은 다시 읽었을 때의 결과를 우선 확인한다.
4. 문서의 판단·수치·검증 설명이 현재 구현과 맞는지 본다. 측정하지 않은 성능과 확인하지 않은 동작은 한계로 남긴다.

기존 검사 중 목적과 응시 규칙에 맞는 것을 사용한다. 검사를 추가하려면 어떤 중요한 오류를 잡는지 설명할 수 있어야 한다. 아래 점검 순서는 모든 검사를 다시 실행하라는 뜻이 아니다.

## 화면이 있는 과제

서버 응답, 실제 포트, `0.0.0.0` 바인딩을 확인한다. 사용자가 내장 Browser에서 수행할 짧은 점검 순서와 예상 결과를 준다. 사람의 결과를 받기 전에는 화면 검사를 미확인으로 둔다.

Computer Use와 브라우저·화면 자동 조작은 사용하지 않는다. 이 키트는 창이 보이지 않는 헤드리스 브라우저 검사도 실행하지 않는다. 도구 이름만으로 배제하지 말고 브라우저를 실행하지 않는 로컬 API·순수 로직 검사는 기존 도구를 활용한다. 기존 테스트에 금지된 동작이 포함돼 있으면 그 부분을 미실행으로 표시하고, 검사를 지우거나 새로 작성해 감추지 않는다.

과제에서 해당 검사를 필수로 요구해 규칙이 충돌하면, 사용자가 Cofa Helper나 운영 측에 확인할 질문을 정리한다. 허용 범위가 확인되기 전에는 금지 동작을 실행하지 않는다.

## 판정과 인계

실패한 필수 조건부터 고치고, 수정의 영향을 받은 검사만 다시 실행한다. 최종 설명에는 확인한 사실, 해결하지 못한 문제, 아직 실행하지 않은 확인을 구별한다. 미실행을 통과로 표시하지 않는다.

제출 전에는 필수 경로와 저장 상태를 확인하도록 안내한다. 충돌이 있으면 바로 저장하거나 다시 불러와 덮어쓰지 않는다. AI가 확인한 디스크 변경과 사용자의 미저장 편집을 구분하고, 필요한 내용을 보존한 뒤 사용자가 선택하게 한다. 제출 미리보기에 보이는 파일이 전부라고 가정하지 않는다.

플랫폼 과제 타이머 종료 10분 전 제출 시작을 고려해 검사를 끝낸다. 제출 확정 버튼은 사용자가 누르며, 이 시점부터 AI 작업을 중단한다. 후속 서술형과 최종 업로드를 마친 완료 화면은 사용자가 직접 확인한다.
